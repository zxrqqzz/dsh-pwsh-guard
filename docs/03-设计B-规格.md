# 03 · 设计（B 方案：守则 + 拦截 + 耗时反馈）

一句话：**三个组件 + 一个会话内存态 —— 看见慢 → 当场教 → 记住（仅本次会话）→ 同类不再拦、只提醒。**

已确认的两个边界：干预范围 = **沙箱内命令**（`danger-full-access` 不碰）；
学习范围 = **会话内**（不落盘、不跨会话、不跨项目）。

```
   pwsh 调用 ──▶ ┌────────────────────────────┐
                │ A 规则引擎 pre-execute      │──deny(reason)──▶ 模型收到替代写法
                └──────────────┬─────────────┘      每会话每规则只拦一次
                               │ allow
                               ▼
                ┌────────────────────────────┐
                │ B 计时 execute（只观测）     │  t0 → next() → t1
                └──────────────┬─────────────┘
                               ▼
                ┌────────────────────────────┐
                │ C 反馈 post-execute         │──additionalContexts──▶ 下次请求里的 notice
                └──────────────┬─────────────┘
                               ▼
                ┌────────────────────────────┐
                │ S 会话内存态                │  WeakMap<agent, SessionState>
                └────────────────────────────┘  会话结束自动回收，不落盘

   守则段 systemPrompt.section（静态，见 01 的证据）
```

---

## A. 规则引擎（`tools/pre-execute`）

**输入**：`exec.name`、`exec.arguments.command`、`exec.agent`。
**输出**：`{kind:'allow'}` 或 `{kind:'deny', reason}`。

判定顺序（短路）：

1. 工具名不在 `config.tools` → allow。
2. **非沙箱会话**（见 A1）→ allow。
3. 命令文本含 `pwsh-guard:allow`（注释逃生口）→ allow。
4. `process.env.PWSH_GUARD_DISABLED === '1'` → allow。
5. 命中 **allowlist** 正则 → allow（必须先判，避免拦掉写得好的命令）：
   `-Filter`、`-Include`、`-Depth`、`-TotalCount`、`-List`、显式单文件 `-Path x.ext`。
6. 逐条规则匹配 `command`，取 `severity` 最高的一条：`block` 族（必然挂）> `search`（必然慢）> 其他。
7. `severity === 'high'`：若该 agent 本会话未被此规则拦过 → `deny`；否则 allow（只教一次）。
   `severity === 'medium'`：永远 allow，只在 C 里出 notice。
8. 其他 → allow。

### A1. 怎么判断「沙箱内」（这是本次新增的关键点，需要实现时确认）

`tools/pre-execute` 的 `exec` 上**没有** sandbox policy 字段（类型里只有 name/arguments/agent/signal）。
三条可选路，实现时按顺序试：

1. `ctx.get('sandboxPolicy')` / `ctx.get('permissions')` 之类服务是否存在——**未验证**，需先 `ctx.get` 探测；
2. 从 `process.env` 或会话配置读当前权限档（read-only / workspace-write / danger-full-access）；
3. **兜底（推荐先用这条）**：不判策略，只在**命令文本**上收敛——规则只针对"枚举/阻塞"类写法，
   而 `danger-full-access` 会话里这些写法照样该被提醒（只是不该 deny）。
   于是实现成：无法判定策略时一律走 `learn`（只 notice 不 deny）。

> 宁可少拦一次，也不要误拦一次。这条是失败安全的延伸。

**deny 的 reason 模板**：

```
[pwsh-guard] 这不是命令失败，是效率建议。
这条会慢：<why>（本机实测：<measured>）
换成：<fast>
（本会话同类写法已提示过；确有必要原样执行请在命令里加注释 # pwsh-guard:allow）
```

首行「这不是命令失败」是硬要求——否则模型会去 debug 一条根本没失败的命令。

## B. 计时（`tools/execute`）

```js
ctx.on('tools/execute', async (exec, next) => {
  const t0 = performance.now();
  const result = await next();
  timing.set(exec, performance.now() - t0);   // WeakMap<exec, ms>
  return result;
});
```

- 类型注释写明「wrappers may change only `exec.signal`」→ **只观测，不改结果**。
- 用 `WeakMap` 把 `ms` 传给 `post-execute`（同一个 `exec` 对象）。
- `tools/execute` 拿不到 `exec.agent`？拿得到（`ToolDispatchExecution` 继承 `ToolExecution`）。

## C. 反馈（`tools/post-execute`）

```js
ctx.on('tools/post-execute', async (exec, result, next) => {
  const downstream = await next();
  const ms = timing.get(exec);
  const notice = decideNotice(exec, downstream, ms);   // undefined = 不说话
  if (!notice) return downstream;
  if (downstream.kind === 'block') return { ...downstream, additionalContexts: [notice, ...(downstream.additionalContexts ?? [])] };
  return { ...downstream, additionalContexts: [notice, ...(downstream.additionalContexts ?? [])] };
});
```

触发条件（任一）：

| 条件 | notice 语气 |
|---|---|
| `ms >= config.slowMs`（默认 5000） | 报耗时 + 给替代写法 |
| 结果文本含 `[timed out after` 或 `result.timedOut` | "把超时跑满了，几乎肯定该换写法或转后台" |
| 命令命中某条 `medium` 规则但没被 deny | 报耗时 + 给替代写法 |
| 同一会话同类命令第 2 次超阈值 | 变短："又 41s。上次给过的写法：<fast>" |

notice 文本（第一次）：

```
[pwsh-guard] 上一条命令实测 48.2s（12,357 个文件进入枚举）。
同一目的的更快写法：<fast>（本机实测 1.2s）
```

`createUserMessage({ content:[{type:'text',text}], source:{ kind:'pwsh-guard', form:'notice', summary } })`
——`source.kind` 必需，照 `dsh-repeat-tool-reminder` 的写法。

## S. 会话内存态

```js
// 每个 agent 一份；agent 是会话内的对象，WeakMap 让会话结束时自动回收
const state = new WeakMap();   // Agent -> { denied:Set<ruleId>, hits:Map<ruleId,{count,maxMs,lastMs}> }
```

- **不落盘**：用户明确「会话内」。不写 `~/.dsh/`，不读 `AGENTS.md`。
- `denied`：每规则只 deny 一次（`denyOncePerSession`，默认 true）。
- `hits`：用于 C 的措辞升级（第 2 次起只说「又慢了」）+ 未来自适应（见 M3）。
- 子代理（subagent）有各自的 agent → 各自独立计数，互不串味。

## 守则段（`systemPrompt.section`，静态）

- `name: 'pwsh-guard'`，`text` 直接读包内 `prompt/section-pwsh-guard.md`（构建时内联成字符串常量，避免运行时读文件）。
- **必须静态**：`AssembleContext` 只有 `scope?`/`signal?`，拿不到 agent，见 `docs/01` 的证据段。
- 长度硬上限 1200 字符；超了裁掉中间条目，保留「外部程序不可用」和 `block` 族。

## 配置

```js
const Config = z.object({
  mode: z.union([z.const('learn'), z.const('guard'), z.const('strict')]).default('guard'),
  tools: z.array(z.string()).default(['pwsh']),
  slowMs: z.number().default(5000),
  denyOncePerSession: z.boolean().default(true),
  maxSectionChars: z.number().default(1200),
  rulesFile: z.string().optional(),                  // 默认用包内内置规则
  silentFamilies: z.array(z.string()).default([])     // 按 family 关掉一类规则
});
```

`mode` 语义：

| mode | deny | notice |
|---|---|---|
| `learn` | 从不 | 全开（含 medium） |
| `guard`（默认） | 仅 high | 全开 |
| `strict` | high + medium | 全开 |

## 失败安全矩阵（写死，不许有例外）

| 情形 | 行为 |
|---|---|
| 规则文件读不到 / JSON 坏 | 用内置兜底规则集（04 的 high 子集），warn 一次 |
| 单条正则编译失败 | 跳过该条，warn，其余照常 |
| 任何 hook 抛异常 | try/catch 包住，异常时 `return next()` / `{kind:'allow'}` |
| `exec.arguments.command` 不是字符串 | allow |
| `exec.agent` 缺失 | 退化为模块级 Set（仍不崩） |
| 无法判定沙箱策略 | 降级为 `learn`（只 notice） |

原则：**guard 只做减法（少教一次），永远不做加法（多拦一次）。**

## 分阶段

| 阶段 | 内容 | 收益 | 风险 |
|---|---|---|---|
| **M1** | 守则段 + 计时 notice（不 deny） | 立刻可见：模型开始知道「刚才那条 40s」 | 零 |
| **M2** | 规则引擎 + deny（once/session） | 「几分钟」在发生前挡掉 | 误拦 → allowlist + 先 learn 跑一周 |
| **M3** | 会话内自适应：某规则在同一 agent 上 `count>=3 且 maxMs>=10s` 时，notice 提前到"预测"语气；`count>=5` 且仍被写 → 允许对本规则解除 once 限制（可配） | 越用越贴手 | 噪音 → 默认关 |

## 已知风险

1. **误拦**：几百个文件的目录上 `Get-ChildItem -Recurse` 也就 30ms。缓解：deny 只给 high + once/session + allowlist；
   命令里出现 `node_modules`、盘符根、`$env:USERPROFILE` 时再升危。
2. **deny 被当成失败**：reason 首行必须写「这不是命令失败」。
3. **守则段占上下文**：硬上限 1200 字符。
4. **`tools/execute` 只能观测**：耗时靠 WeakMap 传给 post-execute。
5. **策略判定不可靠**（A1）：拿不到就降级 learn。
6. 若上游将来给工具结果加 `durationMs`，B 组件退化为纯读字段（盯 changelog）。
