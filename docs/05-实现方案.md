# 05 · 实现方案（语言 / 架构 / 脚手架）

> 本文回答三个问题：**用什么语言**、**要不要架构**、**要不要脚手架/项目框架**。
> 结论先给，理由和证据在后。基于本机已安装 DSH `0.2.1-rc.2` 的实际代码核对（不是推测）。

---

## 0. 一句话结论

**零依赖 ESM 单包（纯 JavaScript + JSDoc 类型检查），不引框架、不建构建链、不用脚手架。**

理由只有一条最硬：**宿主就是 `import()` 一个 ESM 入口**，没有编译期。任何构建链都是给自己加一台需要维护的机器，
而我们要写的东西只有 500–700 行、一个包、五个纯函数模块。

---

## 1. 为什么是纯 JS，不是 TypeScript

| 方案 | 可行性（本机实测） | 结论 |
|---|---|---|
| 纯 ESM JS + `// @ts-check` + 手写 `types/dsh.d.ts` | ✔ 零安装、零构建，`node --test` 直接跑 | **推荐** |
| TypeScript → `tsc` → `lib/` | ✘ 需要 `npm i -D typescript @deepseek-ai/dsh-tools`，而本机沙箱里 **npm/pnpm/node 全部跑不起来**（见 §5），装不了也编译不了 | 暂不选 |
| TS 类型剥离直跑（Node 24 `--experimental-strip-types`） | △ 宿主 Node 版本不确定（社区插件写 `engines: >=22.6`），loader `import()` `.ts` 依赖宿主支持 | 不选 |
| JS 先行、后期迁 TS | ✔ 边界清楚：纯函数模块 + 一个装配层，迁移只动文件后缀和加类型 | 备选 |

**类型收益用 JSDoc 拿大头**：`jsconfig.json` 开 `checkJs`，编辑器（VSCode）里照样有补全和红波浪线，
但没有构建产物、没有 `dist/` 与 `src/` 不一致的风险。`types/dsh.d.ts` 手写宿主契约的**子集**（约 120 行），
文件头标注「来源：@deepseek-ai/dsh 0.2.1-rc.2」，升级时只对照这一个文件即可。

为什么不 `import @deepseek-ai/dsh-tools` 拿官方类型：profile 的 `node_modules` 里**没有** `@deepseek-ai/dsh-*` 包
（只有 `schemastery` / `cosmokit` / 两个 client-ui 包），装成依赖会污染 profile 的依赖树；
官方 `dsh-repeat-tool-reminder` 自己也是把需要的碎片（比如 `createUserMessage`）打进 bundle，用同一策略。

## 2. 为什么不要「架构」

不是不分层，是**不引入抽象**。五个模块全是纯函数 + 一个装配层，模块之间只传普通对象：

```
lib/
├── index.js        # 装配：name/inject/apply + 3 个 hook + section 注册（唯一碰 ctx 的地方）
├── config.js       # 默认值归一化（手写 merge，不引 schemastery）
├── rules.js        # 纯函数：compile / allowlist / match / severity 选择
├── probe.js        # exec/result 防御式读取：命令文本、逃生标记、timedOut、审批标记
├── notice.js       # 纯函数：deny reason / 耗时行 / notice 文本 / 语气升级 / 裁剪
├── state.js        # 会话态：WeakMap<agent, {denied, hits}> + Map<callId, ms>
├── message.js      # createUserMessage（randomUUID + deepFreeze）+ notice 包装
├── compat.js       # 宿主契约适配：sandboxModeOf / sectionOrderOf / 特性检测收口
└── section.js      # 读 prompt/section-pwsh-guard.md（单一真源）+ 内置兜底
prompt/section-pwsh-guard.md   # 守则段正文（唯一真源，852 字符 / 预算 1200）
rules/rules.json               # 规则表：10 条规则 + 5 条 allowlist，自带 samples 用例
scripts/check-host.mjs         # 升级体检：断言 5 个宿主契约仍在
test/*.test.js                 # node:test，零依赖，47 条
```

依赖方向单向：`index → {config, rules, probe, notice, state, section}`，其余模块**互不 import**。
这样单测可以逐个击穿，不需要 mock 整个 ctx。

**唯一的「架构」约束**：所有 `ctx` 交互集中在 `index.js`，其余模块收不到 ctx。
好处是假 ctx 集成测只需要造 4 个方法（`on` / `systemPrompt.section` / `getSectionOrder` / `get`）。

## 3. 为什么不要脚手架 / 项目框架

没有官方脚手架：`dsh plugin` 子命令**只是把参数转发给 pnpm**（`lib/bin.js:116` 原文：forwarding the remaining arguments to pnpm），
`dsh-plugin-manager` 管的是「装/卸/启停」，不生成工程。社区那套（`dsh-plugin` 市场包、`tsdown` 构建）
是**面向发布到 npm 的多包工程**，我们这个是本地开发、单人维护的小插件，套上去只剩成本。

`package.json` 全部内容（除元数据）就这几行：

```json
{
  "type": "module",
  "main": "lib/index.js",
  "exports": { ".": "./lib/index.js", "./package.json": "./package.json" },
  "files": ["lib", "rules", "cordis.patch.yml", "README.md"],
  "engines": { "node": ">=22.19" },
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } },
  "scripts": { "test": "node --test", "check": "node --check lib/index.js" }
}
```

关键字段是 `dsh.bundle.patch` —— 有它，`dsh plugin add` 时安装器才会把包登记进 profile 的 `bundles` 并应用 patch。
`cordis.patch.yml` 只需要一行 insert：

```yaml
- insert:
    - id: pwsh-guard
      name: dsh-pwsh-guard
      config:
        mode: guard
        slowMs: 5000
```

（这套形状照抄装机上的 `dsh-notify`：`name` / `inject` / `apply` 三个导出 + 自带 patch + 零依赖。）

## 4. 设计修正：docs/03 里要改的四处

调研发现文档有 4 处可以写得更准，实现按下面来（这是本文与 01–04 的差异点）：

### 4.1 沙箱档判定：有官方答案了（docs/03 A1 的开放问题关闭）

```js
const svc = ctx.get('sandboxPolicy');
const session = exec.agent?.session ?? ctx.get('sessions')?.get(exec.agent?.id);
const mode = svc?.resolve(session ? { session } : {}).mode;   // 'read-only'|'workspace-write'|'danger-full-access'
```

依据：`dsh-tool-pwsh/lib/index.js:318,321` 自己就是这么调的（`ctx.get("sandboxPolicy")` + `resolve({session: exec.agent.session})`）。
不用猜环境变量，也不用默认降级 `learn`。**判不出才降级 learn**（仍然是失败安全）。

### 4.2 deny 也流经 post-execute（白捡一个能力）

`dsh-repeat-tool-reminder` 的注释原文：*Denied calls count. Detection sits on `tools/post-execute`, which also runs for calls
a `tools/pre-execute` listener denied.*
→ 「拦了模型还在重试」这件事可以被计数，第 2 次起可以换更硬的话术，或者直接升级成 mock 结果。

### 4.3 超时 ≠ 被杀（措辞必须改）

`dsh-tool-pwsh` 的 `promoteOnTimeout` **默认 true**：超时的前台命令不杀，转成后台 job，
模型看到的是 `[still running after Nms]`。所以 block 族的反馈不能写「被杀掉了白等」，要写
「已经挂满超时，现在转成后台 job 了，用 `job_output` 收；下次别在前台等」。

### 4.4 守则段的 order 用官方分配表

`ctx.systemPrompt.getSectionOrder('TOOL_PWSH')` = 1010 → 我们注册 order `1011`，紧跟 pwsh 工具说明。
不要自己拍一个数字（上游以后插段会撞）。

## 5. 本机沙箱限制（影响交付方式，必须先说清）

实测（本轮，`workspace-write` 模式）：

| 操作 | 结果 |
|---|---|
| 读 DSH 安装目录 `.d.ts` | ✔ 可以 |
| 写本项目目录 | ✔ 可以 |
| `node -v` / `node --test` | ✘ `[sandbox: file access denied under workspace-write mode]` |
| `& git --version` / `& cmd /c echo` | ✘ `Access is denied`（docs/02 B 节同一现象） |
| `Start-Process ... -RedirectStandardOutput` 绕行 | ✘ 同样 Access denied |
| 写 `~/.dsh/profiles/web/cordis.patch.yml` | ✘ 在 workspace 外 |
| 联网 `npm view` / `Invoke-WebRequest` | ✘ 连不上 |

**结论：我能写代码和测试，但跑不了测试、装不了插件。**

验证三条路（要你选一条）：

- **A（推荐）**：需要验证时我发起一次 `danger-full-access` 升级审批，你点同意，我当场跑 `node --test`；
- **B**：你在外部终端 `cd D:\Xjk\vscode\DSH\Mods_Project\dsh-pwsh-guard; node --test`，把输出贴回来；
- **C**：只写不跑，装好后在真实会话里看效果（最慢，但零审批摩擦）。

安装同理三选一：`dsh plugin --profile web add D:\...\dsh-pwsh-guard`（终端）／GUI 侧边栏 **Plugins** 页填绝对路径／手工在
`~/.dsh/profiles/web/cordis.patch.yml` 加那 5 行 insert。

## 6. 里程碑（按你选的 M1 起）

| 阶段 | 交付 | 验收 |
|---|---|---|
| **M1**（本轮目标） | 骨架 + package.json + patch + 守则段 + 计时（**两条路反馈**）+ 假 ctx 冒烟测 | 新会话 system prompt 里能看到守则段；`Start-Sleep 6` 之后结果末尾出现 `[pwsh-guard] 6.x s` |
| **M2** | 规则引擎 + `rules.json` + deny（每会话每规则一次）+ allowlist + `# pwsh-guard:allow` + 规则回归测（hit/miss 全跑） | 验收 2/3/5 条；`Get-ChildItem -Recurse` 被拦一次，带 `-Filter` 的不拦 |
| **M3** | 会话内自适应（同类第 3 次换语气、可配解除 once） | 同会话连续三次同类慢命令，notice 逐次变短 |

配置项（M1 就要能改）：

```yaml
mode: guard                 # learn | guard | strict
tools: [pwsh]
slowMs: 5000
denyOncePerSession: true
noticeOnDenyRetry: true
maxSectionChars: 1200
rulesFile: null             # 默认包内 rules/rules.json
silentFamilies: []
```

## 7. 两条路反馈的语义（你已经选定的）

| 通道 | 内容 | 何时 |
|---|---|---|
| 工具结果末尾追加一行 | `[pwsh-guard] 48.2s`（纯数字，不提建议） | `ms >= slowMs` 或 `timedOut` |
| notice（`additionalContexts`） | 「慢在哪 + 换成什么写法 + 本机实测数字」 | 命中规则 / 超时 / 同一会话同类第 N 次 |

分工原则：**结果行负责「让模型无法忽略」，notice 负责「教它改」**。两边不重复同一句话。

## 8. 待你拍板的三个点

1. **语言/工具链**：纯 JS + JSDoc（推荐）／ TS + tsc（需要你在沙箱外装依赖）／ JS 先行后期迁 TS
2. **工程形态**：单包直出（推荐）／ pnpm workspace monorepo（为以后多插件留位置）
3. **验证方式**：A 放行审批（推荐）／ B 你跑／ C 只写不跑
