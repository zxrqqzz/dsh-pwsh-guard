## 为什么守则段必须是静态的（证据）

`dsh-system-prompt/lib/types/index.d.ts`：

```ts
export interface AssembleContext {
  scope?: ScopeKey;        // 参与装配的 scope
  signal?: AbortSignal;    // 发起装配的 turn 的控制信号
}
```

**没有 agent，也没有 session id。** 所以 `PromptSection.text` 的函数形式拿不到「是哪个会话在读」，
任何「本项目最近踩过什么」的动态渲染都不可靠（只能退化成进程级全局，那正好是用户否掉的选项）。

结论：守则段 = 纯静态通则；个性化学习只走 `additionalContexts` notice（它天然是会话内的）。

## 明确不做

- 不做 token 压缩 / 输出格式化（rtk 的活）。
- 不静默改写命令（C 方案不实现）。
- 不落盘、不做跨会话画像。
- 不拦网络、安装、编译这类「本来就慢但必须跑」的命令——只拦**写法导致的慢**。
- 不接管审批流（`ask` 决策不使用）。
- 不修改用户的 `AGENTS.md`。
